# 이미지 AI 최종 50장 검증 및 MVP 인수인계 보고서

## 1. 최종 구성

| 구분 | 확정 내용 |
| --- | --- |
| 이미지 정보 추출 | Qwen3-VL 8B Instruct |
| 이미지 프롬프트 | `prompts/analyze_image_fast.txt` 축약 균형형 |
| Ollama 최적화 | Flash Attention, 모델 워밍업, `keep_alive: -1` |
| 컨텍스트 | 6144 |
| 카테고리 분류 | qwen3:8b |
| 카테고리 프롬프트 | `ai-text/prompts/category-prompt-v1.txt` 다중 분류형 |
| 다중 할당 | 2순위 45% 이상, 1순위와 10%p 이하, 최대 2개 |
| 이미지 입력 | JPEG, MPO, PNG, WEBP, HEIC/HEIF, 최대 20MB |
| 전처리 | EXIF 회전, RGB 변환, 최대 2048px 리사이즈, JPEG 변환 |
| 실행 방식 | 저장 API와 분리된 비동기 처리 |

이미지 모델은 카테고리를 직접 선택하지 않는다. 제목·설명·태그·OCR·객체를 추출하고,
해당 정보를 `classificationText`로 변환해 qwen3:8b 분류 모델에 전달한다.

일반 사진, 상품 화면, 앱 화면, 문서와 OCR 중심 이미지 모두 유효한 JSON으로 추출됐다.
이미지 전처리와 구조화 출력은 MVP 적용 가능한 수준이다.

처리 시간은 동기 저장 요청에 넣기에는 길다. Redis Streams 비동기 처리와
`PROCESSING` 상태 조회를 반드시 유지해야 한다.

GPS와 촬영 시각은 모델 추정이 아니라 원본 EXIF 값만 사용한다. EXIF가 없는
스크린샷·다운로드·생성 이미지는 `null`이 정상이다.

### 2.1 최종 프롬프트 전체 회귀

전체 50장 결과의 정확도 기준을 유지하면서 반복 지시와 장황한 출력 요구를 축약했다.
모델, 이미지 전처리, 최대 출력 토큰은 변경하지 않았다.

| 항목 | 이전 균형형 | 최종 축약형 | 변화 |
| --- | ---: | ---: | ---: |
| 성공률 | 100% | 100% | 유지 |
| 평균 처리 시간 | 32.20초 | 26.78초 | **16.8% 단축** |
| 평균 출력 토큰 | 343.42 | 287.76 | 16.2% 감소 |
| 핵심 개념 재현율 | 83.4% | 81.4% | -2.0%p |
| OCR 핵심어 재현율 | 86.7% | 85.3% | -1.4%p |
| P95 처리 시간 | 49.33초 | 62.37초 | 증가 |

최종 원본 결과:

```text

```

평균 속도는 개선됐지만 긴 OCR·상품 화면은 출력량에 따라 1분 이상 소요된다. 정확도
보호를 위해 최대 이미지 크기 2048px와 최대 출력 2000토큰은 유지한다. 추가 단축은
정보 누락 가능성이 있어 MVP 최종 설정에서는 적용하지 않는다.

### 최종 수치 해석

최신 보고서의 100%는 `acceptable_categories`를 포함한 의미상 허용 정답 기준이다.

- 평가 기준상 Top-1 정답: **50/50**
- 평가 기준상 정답 포함: **50/50**
- 단일 대표 정답만 엄격히 비교: **47/50 (94.0%)**

대표 정답과 다른 허용 정답을 선택한 사례는 세 장이다.

## 4. 적용한 카테고리 개선

- 일반 반려동물·인물·사물 사진은 목적이 없으면 기타로 분류
- 사진·스크린샷이라는 형식 자체를 문화·콘텐츠 근거로 사용하지 않음
- 건강·운동, 생활·할 일, 여행·장소, 문화·콘텐츠 경계 기준 명시
- 모든 후보를 내부 비교하고 상위 후보 2개를 점수순으로 반환
- 기타가 1순위이면 기타만 반환
- 배경·장소·도구·브랜드만으로 2순위 카테고리를 추가하지 않음
- 45%·10%p 다중 할당 정책을 후처리에 적용
- 장소 방문과 관람, 장소와 운동처럼 실제 복수 해석이 가능한 정답을 허용

## 5. 과적합 및 일반화 판단

최종 50장은 프롬프트를 수정하는 데 사용한 개발 세트다. 따라서 100% 결과는
새로운 사용자 이미지에 대한 일반화 성능 보장이 아니다.

프롬프트는 특정 파일명이나 정답을 직접 암기하도록 작성되지는 않았고, 카테고리 경계와
판단 원칙 중심이므로 구조 자체는 실서비스 적용에 적합하다. 다만 다음 단계에서는 이
50장에 맞춘 규칙을 더 추가하지 않는다.

권장 검증:

1. 현재 50장을 프롬프트 개발 세트로 고정한다.
2. 팀원이 새로 제공한 미사용 이미지 50~100장을 홀드아웃 세트로 구성한다.
3. 프롬프트를 수정하지 않고 한 번만 실행한다.
4. 대표 라벨 정확도와 허용 정답 정확도를 분리해 기록한다.
5. 사용자 수정 카테고리를 실제 운영 정답으로 수집한다.

## 6. 백엔드 전달 가능 여부

### 이미지 AI에서 전달 가능한 부분

- 이미지 형식·크기 검증과 HEIC/HEIF 지원
- EXIF 회전, RGB 변환, 최대 2048px 리사이즈
- 구조화 이미지 정보 추출
- JSON 검증·복구, OCR·태그·객체 정규화
- 오류 코드와 최대 2회 재시도
- 실제 EXIF 촬영 시각과 GPS 좌표 추출
- HTTP 상태 확인 및 분석 엔드포인트
- qwen3:8b 입력용 `classificationText`

### 백엔드에서 아직 필요한 부분

현재 백엔드는 이미지 AI와 즉시 연결된 상태가 아니다.

1. `ImageTextExtractor` 실제 구현이 없고 NoOp 빈만 존재한다.
2. `ImageTextExtractor.extract(byte[])`가 `String`만 반환해 구조화 결과와 EXIF를
   받을 수 없다.
3. `Item`에 `latitude`, `longitude`, `capturedAt`, `placeName` 필드가 없다.
4. 좌표를 장소명으로 바꾸는 지도 어댑터가 없다.
5. AI 서버 주소·연결 제한 시간·재시도 설정 연결이 필요하다.

결론적으로 **이미지 AI 모듈은 인수인계 가능하지만 백엔드 엔드투엔드 연동은
백엔드 구현이 더 필요하다.**

## 7. 권장 연결 흐름

```text
이미지 저장 요청
→ S3 원본 저장 및 Item PROCESSING 즉시 응답
→ Redis Streams 작업 소비
→ POST /v1/images/analyze
→ 이미지 결과 저장 및 classificationText를 qwen3:8b에 전달
→ 카테고리 후처리
→ GPS가 있으면 지도 어댑터로 장소명 역지오코딩
→ 카테고리·좌표·촬영시각·장소명 저장
→ DONE 또는 PARTIAL
```

이미지 AI 성공 응답:

```json
{
  "success": true,
  "result": {
    "title": "이미지 제목",
    "description": "이미지 설명",
    "tags": ["검색 태그"],
    "ocr_text": "OCR 원문",
    "objects": ["주요 객체"],
    "confidence": 0.95
  },
  "classificationText": "이미지 설명: ...",
  "metadata": {
    "latitude": 35.163414,
    "longitude": 126.9205017,
    "captured_at": "2019-09-03T23:55:27"
  }
}
```

장소명은 이미지 AI가 추측하지 않는다. 백엔드 지도 어댑터가 좌표를 역지오코딩해
`placeName`을 생성한다.

## 8. MVP 적용 판단

| 영역 | 판단 |
| --- | --- |
| 이미지 정보 추출 | **적용 가능** |
| 모바일 이미지 전처리 | **적용 가능** |
| JSON 검증·오류 처리 | **적용 가능** |
| EXIF 좌표·촬영시각 | **적용 가능** |
| 카테고리 분류 | **MVP 적용 가능, 사용자 수정 필수** |
| 백엔드 HTTP 연결 | **백엔드 구현 필요** |
| 장소명 역지오코딩 | **백엔드 구현 필요** |

카테고리 점수는 실제 확률이 아니라 후보 간 상대 적합도다. 사용자가 자동 분류 결과를
수정할 수 있게 하고, 수정 데이터를 이후 임계값 조정에 사용한다.

## 10. 인수인계 순서

1. 백엔드 담당자에게 이 보고서와 `docs/image-ai-contract.md`를 공유한다.
2. GPU 장비에서 Ollama와 이미지 AI 서버를 실행하는 배포 구조를 확정한다.
3. 백엔드가 `POST /v1/images/analyze` 호출 어댑터를 구현한다.
4. `String ImageTextExtractor`를 구조화 DTO 계약으로 확장한다.
5. Item과 DB에 좌표·촬영시각·장소명 필드를 추가한다.
6. 지도 어댑터에서 좌표를 장소명으로 역지오코딩한다.
7. Redis 작업 한 건으로 저장부터 `DONE/PARTIAL`까지 통합 테스트한다.
8. AI 실패 시 원본 저장은 유지되고 재처리 가능한지 확인한다.

## 12. 최종 결론

- Qwen3-VL 이미지 추출 모듈은 MVP 인수인계 가능 상태다.
- 최종 축약 프롬프트 50장 성공률 100%, 평균 26.78초, 핵심 개념 81.4%, OCR 85.3%다.
- 최신 50장 분류는 허용 정답 기준 100%, 대표 라벨 엄격 기준 94%다.
- 분류 수치는 이전 이미지 추출 결과 기반이며, 100%는 개발 세트 결과라 신규 이미지
  성능 보장이 아니다.
- 저장 API와 AI 호출은 반드시 비동기로 유지한다.
- 사용자 카테고리 수정 기능을 함께 제공한다.
- 백엔드 HTTP 어댑터, 구조화 DTO, 위치 저장과 역지오코딩 구현이 남아 있다.
