# AI 텍스트 테스트: 로컬 모델과 API 모델 종합 비교

> 이 보고서는 2026-07-21 당시의 이전 카테고리 체계(`개발·IT`, `업무·프로젝트` 포함)로 실행된 역사적 결과다. 2026-07-22 확정된 새 카테고리 체계의 성능을 의미하지 않으며, 새 체계에서는 재실행 후 별도 비교가 필요하다.

## 1. 보고서 목적

우주인 서비스의 텍스트 메모 처리에 사용할 모델을 검토하기 위해 로컬 Ollama 모델과 SSAFY GMS를 통한 OpenAI API 모델을 동일한 데이터와 평가 코드로 비교했다.

이번 테스트에서 확인하려던 핵심 질문은 다음과 같다.

1. 카테고리 분류만 요청했을 때 어떤 모델이 가장 정확하고 빠른가?
2. 요약만 요청했을 때 정해진 JSON 구조와 1~3문장 제약을 안정적으로 지키는가?
3. 태그와 키워드를 생성했을 때 원문에 근거한 검색용 메타데이터를 만드는가?
4. 요약·분류·메타데이터를 한 번에 생성하면 단일 작업 대비 성능이 떨어지는가?
5. 로컬 실행과 API 실행의 지연 시간, 토큰, 운영 조건에는 어떤 차이가 있는가?

## 2. 비교 대상과 조건

| 구분 | 모델 | 실행 방식 |
|---|---|---|
| 로컬 | Qwen3 4B | Ollama |
| 로컬 | Qwen3 8B | Ollama |
| API | GPT-5 nano | SSAFY GMS Chat Completions |
| API | GPT-5 mini | SSAFY GMS Chat Completions |

- 데이터: 카테고리 폴더에 정리된 메모 23건
- 테스트 모드: `category-only`, `summary-only`, `metadata-only`, `integrated`
- 동일 조건: 데이터 순서, 카테고리 목록과 설명, 프롬프트 버전, JSON Schema, 자동 평가 코드
- 로컬 결과는 모델별 최초 COLD 호출 1건이 추가되어 호출 수가 24건으로 표시된다. 정확도와 평균 WARM 성능은 실제 데이터 23건을 기준으로 계산됐다.
- API 결과는 모델별 데이터 23건을 각 1회 호출했다.
- OpenAI API는 temperature와 seed를 적용하지 않았으므로 로컬과 생성 파라미터가 완전히 같지는 않다.

## 3. 핵심 결론

1. **분류 정확도는 Qwen3 8B가 가장 높았다.** `category-only`와 `integrated` 모두 87.0%였다.
2. **응답 속도는 Qwen3 4B가 모든 모드에서 가장 빨랐다.** 복합 처리 평균도 약 3.73초였다.
3. **API 모델 중에서는 GPT-5 mini가 GPT-5 nano보다 모든 주요 지표에서 유리했다.** 분류 정확도가 높고, 더 빠르며, 출력·추론 토큰도 적었다.
4. **검색용 키워드의 원문 근거 비율은 GPT-5 mini가 86.5%로 가장 높았다.** 메타데이터 생성만 보면 mini의 장점이 뚜렷했다.
5. **API 모델은 복합 작업에서 분류 정확도가 4.3%p 하락했다.** 반면 두 로컬 모델의 정확도는 단일 분류와 복합 처리에서 동일했다.
6. 모든 모델의 응답·JSON·Schema 성공률이 100%였으므로 이번 데이터에서는 형식 안정성보다 정확도, 지연 시간, 의미 품질이 더 중요한 구분 기준이다.
7. 요약의 의미 품질을 판정할 정답과 수동 평가가 없어, 현재 결과만으로 어떤 모델의 요약이 가장 좋은지는 결정할 수 없다.

## 4. Category-only: 순수 분류 성능

### 알아내고 싶었던 내용

- 요약이나 태그 생성 없이 분류에만 집중했을 때의 순수 정확도
- 카테고리 불균형을 고려한 Macro F1
- 모델이 제시한 confidence가 실제 정답 여부와 구분되는지
- 분류 한 건에 필요한 평균 응답 시간

### 결과

| 모델 | Accuracy | Macro F1 | 평균 confidence | 평균 응답 시간 | P95 |
|---|---:|---:|---:|---:|---:|
| Qwen3 8B | **87.0%** | **87.3%** | 0.928 | 2.04초 | 2.45초 |
| Qwen3 4B | 82.6% | 82.4% | 0.939 | **1.36초** | **1.51초** |
| GPT-5 mini | 82.6% | 86.2% | 0.940 | 2.78초 | 3.87초 |
| GPT-5 nano | 73.9% | 78.0% | 0.855 | 8.38초 | 16.36초 |

### 해석

- 최고 정확도는 Qwen3 8B였다.
- Qwen3 4B와 GPT-5 mini의 Accuracy는 같지만 mini의 Macro F1이 더 높았다. mini가 카테고리별 성능을 조금 더 균형 있게 유지했다는 의미다.
- Qwen3 4B는 Qwen3 8B보다 정확도가 4.4%p 낮지만 약 33% 빠르다.
- GPT-5 nano는 가장 낮은 정확도와 가장 긴 지연 시간을 보여, 현재 분류 용도에서는 선택 근거가 약하다.
- 모든 모델의 confidence가 높은 편이다. 오답에서도 Qwen3 4B 0.925, Qwen3 8B 0.900, GPT-5 mini 0.895, GPT-5 nano 0.773으로 나타나 confidence만으로 오분류를 안전하게 걸러내기는 어렵다.

## 5. Summary-only: 요약 형식과 운영 성능

### 알아내고 싶었던 내용

- 요약만 요청하면 JSON과 1~3문장 제약을 안정적으로 지키는가?
- 복합 요청보다 빠르고 적은 토큰으로 요약할 수 있는가?
- 정답 데이터가 있는 경우 필수 키워드, 핵심 내용, 금지 표현을 얼마나 잘 처리하는가?

### 결과

| 모델 | 응답·JSON·Schema 성공률 | 평균 응답 시간 | P95 | 평균 입력 토큰 | 평균 출력 토큰 |
|---|---:|---:|---:|---:|---:|
| Qwen3 4B | 100% | **2.43초** | **2.83초** | 222 | 76 |
| GPT-5 mini | 100% | 3.78초 | 5.05초 | 232 | 355 |
| GPT-5 nano | 100% | 6.64초 | 10.04초 | 232 | 819 |
| Qwen3 8B | 100% | 8.04초 | 11.34초 | 228 | 65 |

### 해석

- 네 모델 모두 형식 제약은 완벽하게 지켰다.
- 로컬 Qwen3 4B가 가장 빨랐으며 출력 토큰도 적었다.
- GPT-5 nano는 mini보다 출력 토큰을 약 2.3배 사용하면서도 더 느렸다. 추론 토큰 사용량이 큰 것이 주요 원인으로 보인다.
- Qwen3 8B는 출력이 짧지만 생성 속도가 느려 평균 지연 시간이 가장 길었다.
- 메모 데이터에는 `requiredKeywords`, `summaryPoints`, `forbiddenClaims` 정답이 없으므로 의미 평가 결과는 0%가 아니라 N/A이다. 현재는 “형식에 맞는 요약을 생성했다”까지만 확인됐으며, “좋은 요약이다”라고 결론 내릴 수 없다.

## 6. Metadata-only: 검색용 태그와 키워드

### 알아내고 싶었던 내용

- 태그와 키워드 개수 및 중복 금지 규칙을 지키는가?
- 생성된 키워드가 원문에 실제로 존재해 검색 근거로 사용할 수 있는가?
- 메타데이터만 별도로 생성할 때의 속도와 토큰 사용량은 어느 정도인가?

### 결과

| 모델 | JSON·Schema 성공률 | 원문 키워드 비율 | 평균 응답 시간 | 평균 출력 토큰 |
|---|---:|---:|---:|---:|
| GPT-5 mini | 100% | **86.5%** | 7.79초 | 743 |
| Qwen3 4B | 100% | 64.3% | **2.81초** | 89 |
| Qwen3 8B | 100% | 62.6% | 7.25초 | **64** |
| GPT-5 nano | 100% | 52.2% | 11.22초 | 1,656 |

### 해석

- 네 모델 모두 태그·키워드 구조와 개수 제약을 지켰다.
- GPT-5 mini는 생성 키워드가 원문에 직접 존재하는 비율이 가장 높아 검색용 메타데이터의 근거성이 좋았다.
- Qwen3 4B는 mini보다 원문 키워드 비율이 낮지만 약 2.8배 빠르고 출력 토큰도 훨씬 적다.
- GPT-5 nano는 원문 근거 비율이 가장 낮고 출력 토큰과 지연 시간이 가장 커서 이번 메타데이터 용도에서는 비효율적이었다.
- 원문에 직접 없는 동의어가 검색에 유용할 수도 있으므로 원문 키워드 비율만으로 의미 품질 전체를 판단해서는 안 된다. 실제 검색 성공률 평가는 별도로 필요하다.

## 7. Integrated: 실제 서비스형 복합 출력

### 알아내고 싶었던 내용

- 요약·카테고리·태그·키워드를 한 번에 요청해도 형식을 안정적으로 지키는가?
- 단일 분류보다 복합 작업에서 카테고리 성능이 떨어지는가?
- 실제 서비스 요청 한 건에 필요한 지연 시간과 토큰은 어느 정도인가?

### 결과

| 모델 | Accuracy | Macro F1 | 평균 응답 시간 | P95 | 건당 입력 토큰 | 건당 출력 토큰 | 건당 합계 |
|---|---:|---:|---:|---:|---:|---:|---:|
| Qwen3 8B | **87.0%** | **86.7%** | 7.61초 | 9.02초 | 1,226 | 123 | 1,350 |
| Qwen3 4B | 82.6% | 82.4% | **3.73초** | **4.79초** | 1,220 | 149 | **1,369** |
| GPT-5 mini | 78.3% | 82.0% | 6.08초 | 9.45초 | 1,318 | 662 | 1,981 |
| GPT-5 nano | 69.6% | 73.3% | 10.02초 | 14.13초 | 1,318 | 1,410 | 2,728 |

토큰 측정 방식은 Ollama와 GMS API가 다를 수 있으므로 로컬과 API 토큰 수를 절대적으로 동일한 단위처럼 비교해서는 안 된다.

### 단일 분류 대비 복합 처리의 정확도 변화

| 모델 | Category-only | Integrated | 변화 |
|---|---:|---:|---:|
| Qwen3 8B | 87.0% | 87.0% | 0.0%p |
| Qwen3 4B | 82.6% | 82.6% | 0.0%p |
| GPT-5 mini | 82.6% | 78.3% | -4.3%p |
| GPT-5 nano | 73.9% | 69.6% | -4.3%p |

### 해석

- 네 모델 모두 복합 JSON Schema를 100% 지켜 형식 통합 자체는 가능하다.
- 로컬 모델은 복합 출력에서도 분류 정확도가 유지됐다.
- 두 API 모델은 복합 작업에서 분류 정확도가 각각 4.3%p 하락했다. 한 번의 프롬프트에서 여러 작업을 동시에 수행할 때 분류 집중도가 낮아질 가능성이 있다.
- GPT-5 mini는 23건에서 입력 30,318토큰, 출력 15,234토큰으로 총 45,552토큰을 사용했다.
- GPT-5 nano는 입력 30,318토큰, 출력 32,432토큰으로 총 62,750토큰을 사용했다. mini보다 전체 토큰을 약 38% 더 사용했다.
- 출력 토큰 안에 포함된 추론 토큰은 mini가 건당 약 526, nano가 약 1,274였다. nano의 긴 추론이 높은 정확도로 이어지지 않았다.

## 8. 운영 관점 비교

| 관점 | 로컬 Ollama | SSAFY GMS API |
|---|---|---|
| 데이터 외부 전송 | 없음 | GMS 엔드포인트로 전송 |
| 네트워크 의존성 | 낮음 | 있음 |
| 실행 비용 | 로컬 CPU/GPU·메모리 사용 | GMS 정책·쿼터 및 API 사용량 |
| 초기 준비 | 모델 다운로드와 실행 환경 필요 | GMS 키와 네트워크 필요 |
| 속도 영향 | 장비 성능과 모델 크기에 좌우 | 서버 상태와 네트워크에 좌우 |
| 확장성 | 장비 자원 한도 내에서 직접 관리 | API 제공 범위에서 확장 용이 |
| 토큰 비용 계산 | 직접적인 API 과금 없음 | 가격 설정이 없어 현재 N/A |

이번 실행에서는 모든 호출이 성공했지만, API 방식은 인증 오류, 요청 제한, 네트워크 장애를 운영 시 고려해야 한다. 로컬 방식은 외부 장애에 덜 의존하지만 사용자 증가 시 동시 처리 자원과 큐 관리가 필요하다.

## 9. 모델 선택 제안

### 정확도를 최우선으로 할 때

현재 23건 기준으로는 **Qwen3 8B**가 가장 좋은 분류 결과를 냈다. 다만 요약·메타데이터 생성 시간이 길고 로컬 자원 사용량이 크다.

### 속도와 운영 비용을 우선할 때

**Qwen3 4B**가 가장 현실적인 로컬 기준점이다. 분류 정확도 82.6%를 유지하면서 모든 모드에서 가장 빠르고, 복합 작업에서도 정확도 하락이 없었다.

### API 모델을 사용해야 할 때

**GPT-5 mini**를 우선 후보로 보는 것이 타당하다. nano보다 정확하고 빠르며 토큰도 적게 사용했고, 원문 기반 키워드 생성 비율은 전체 모델 중 가장 높았다.

### 현재 GPT-5 nano의 위치

이번 데이터에서는 mini보다 정확도, 속도, 토큰 효율, 원문 키워드 비율이 모두 낮았다. 별도의 비용 또는 쿼터상 이점이 확인되지 않는 한 운영 후보로 선택할 근거가 부족하다.

### 기능 분리 여부

- 분류가 중요하면 `category-only`를 별도로 호출하는 편이 API 모델의 정확도에 유리했다.
- 로컬 모델은 integrated에서도 분류 정확도가 유지되어 한 번의 복합 호출로 단순화할 가능성이 있다.
- 다만 호출을 분리하면 전체 지연 시간과 요청 수가 증가하므로 실제 서비스에서는 정확도 요구 수준과 처리 비용을 함께 판단해야 한다.

## 10. 현재 테스트의 한계와 다음 확인 항목

1. 데이터가 23건으로 작고 카테고리별 표본 수가 적어 결과 변동 가능성이 크다.
2. 파일이 위치한 카테고리 폴더명을 정답으로 사용했으므로 일부 메모는 사람도 여러 카테고리로 해석할 수 있다.
3. 요약 정답과 수동 평가가 없어 요약의 사실성, 정보 보존, 가독성을 모델 간 비교하지 못했다.
4. 태그·키워드도 검색 성공률이나 사용자 선택률로 평가하지 않았다.
5. 모든 모델을 한 번씩만 실행해 출력 변동성과 재현성을 충분히 측정하지 못했다.
6. 로컬과 API의 토큰 측정 기준 및 실행 환경이 달라 토큰과 지연 시간을 완전히 동일 조건으로 볼 수 없다.
7. GMS 가격과 쿼터 정보가 설정되지 않아 실제 비용 비교는 N/A이다.

다음 단계에서는 카테고리별 표본을 늘리고, 대표 메모에 `requiredKeywords`, `summaryPoints`, `forbiddenClaims` 정답을 추가한 뒤 요약 수동 평가를 병행하는 것이 필요하다. 실제 검색 시나리오에서 태그·키워드의 검색 적중률도 별도로 측정해야 한다.
