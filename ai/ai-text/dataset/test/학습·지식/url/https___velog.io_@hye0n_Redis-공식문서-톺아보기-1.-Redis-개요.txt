Key: 데이터를 식별하는 고유한 이름이다. '바이너리 세이프(Binary Safe)'하여 문자열뿐만 아니라 이진 데이터도 키로 사용할 수 있다. 일반적으로는 콜론(:)으로 구분된 네임스페이스 단위의 문자열 key 를 사용한다. Value: 키에 매핑되는 실제 데이터. 문자열 대신 다양한 자료구조를 담을 수 있다. String: 범용 value container Hash: 하나의 키 안에 여러 필드와 값 쌍을 저장하는 맵 구조. (ex. 사용자 프로필) List: 큐 (ex. 메시지 큐) Set: 순서 없고 중복 없는 집합 (ex. 방문자 IP) Sorted Set (ZSET): 정렬된 Set (ex. 실시간 랭킹) HyperLogLog: 중복을 제거한 서로 다른 값의 개수(cardinality)를 적은 메모리로 근사 계산한 값 (ex. 방문자 수) Geospatial: 위치 인덱스 Stream : append-only 로그 구조의 메시지 스트리밍 데이터 타입 ⇒ Redis Streams 에서 쓰는 데이터 타입이다. Redis의 기능 1. 데이터베이스 (Database) Redis 는 in-memory 기반이지만, Persistence(지속성/영속성) 기능을 제공하기 때문에 데이터베이스로 사용될 수 있다. RDB(스냅샷) 와 AOF(Append Only File) 방식을 통해 Redis memory 의 값을 disk 에 쓴다.(persist) 이를 통해 서버가 재시작되어도 데이터를 복구할 수 있어서 disk DB 의 특성을 가질 수 있다. 당연히 그렇다고 해서 redis 를 disk 기반 DB로 대체해서 쓰라는 뜻은 아니다. 값이 만야 휘발되지 않는다는 뜻이다. 세션 저장소, 실시간 순위표(Sorted Set 활용) 등으로 사용된다. 2. 캐시 (Cache) 데이터가 memory 에 있기 때문에 접근 속도가 disk 기반 DB보다 빠르다. 자주 조회되는 데이터를 Redis 에 저장해두고, 만료 시간(TTL) 설정이나 메모리 관리 정책(Eviction Policy)를 통해 캐시로 활용한다. 메모리 관리(Eviction Policy)는 LRU(Least Recently Used), LFU(Least Frequently Used) 알고리즘을 사용해서 오래됐거나 덜 사용하는 데이터를 삭제한다. 3. 메시지 브로커 (Message Broker) 애플리케이션 간의 비동기 통신을 중개하는 메시지 브로커로 사용된다. Pub/Sub (발행/구독) : UBLISH와 SUBSCRIBE 명령어를 사용하여, 게시자(Publisher)가 특정 채널에 메시지를 보내면 해당 채널을 구독 중인 모든 수신자(Subscriber)에게 실시간으로 메시지를 전달한다. 채팅 시스템이나 실시간 알림에 사용된다. 메시지 큐(Message Queue) : Redis 의 List 자료구조를 활용해 LPUSH(왼쪽삽입), RPOP(오른쪽제거)를 사용하여 큐를 구현할 수 있다. 4. 스트림 (Streams) Redis 5.0부터 도입된 Stream 자료구조를 사용해 대용량 데이터 스트리밍을 처리할 수 있다. Stream 자료구조는 로그 파일처럼 데이터가 추가만 되는(append-only) 구조이다. Consumer Groups 기능으로 여러 Consumer 가 스트림 데이터를 나누어 처리할 수 있다. (Kafka 경량화 버전) 5. 문서 데이터베이스 (Document DB) JSON 자체를 저장하고, 인덱싱 및 빠른 검색을 지원한다. JSON value 를 string으로 직렬화해서 저장하는 방식이 아니라, JSON 형식 문서를 네이티브 JSON 타입으로 저장할 수 있다. Atomic Operations: 문서 전체를 가져와서 수정하고 다시 덮어쓸 필요 없이, JSON.SET이나 JSON.GET과 같은 명령어로 특정 필드 값만 원자적으로 조회하거나 업데이트할 수 있다. Indexing & Full-Text(FT)Search: RediSearch 모듈을 사용해서 JSON 문서 내부의 필드 값을 기준으로 인덱스를 생성하고 고속 검색을 수행할 수 있다 (FT 접두사 명령어) 6. 벡터 데이터베이스 (Vector DB) 데이터베이스 관점에서 Vector 는 데이터의 특징(Feature)를 나타내는 실수 배열이다. 텍스트, 이미지, 비디오 등의 데이터를 벡터 배열로 변환하는 과정을 벡터 임베딩이라 하고, 벡터 임베딩은 임베딩 모델을 통해 수행된다. 벡터 배열은 의미가 비슷한 데이터일수록 벡터 공간에서 서로 가까이 위치한다. Redis 는 이렇게 생성된 벡터 배열을 저장하고, 인덱싱해서 벡터 간 유사도 검색을 지원한다.
