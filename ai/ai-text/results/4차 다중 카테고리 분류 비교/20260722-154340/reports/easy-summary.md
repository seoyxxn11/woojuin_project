# 4차 다중 카테고리 분류 결과 — 쉬운 요약

## 한 줄 결론

현재 서비스 후보로는 **`split-with-description` + 임계값 `0.65`**가 가장 균형이 좋다.

- 모델: `qwen3:8b`
- 데이터: 78건
- 권장 조건: 분리형(split), 카테고리 설명 포함, 임계값 0.65
- 모델 Top-1 정확도: **82.1%** (64/78건)
- 완화 정확도: **87.2%** (68/78건)
- 서비스 후처리 포함 정답 포함률: **93.6%** (73/78건)
- 평균 처리 시간: **약 2.73초/건**

단, 78건을 한 번만 실행한 결과이므로 최종 확정값보다는 **현재 후보 선정 결과**로 보는 것이 안전하다.

## 무엇을 비교했나

두 가지 요소를 조합해 총 4개 조건을 비교했다.

| 구분 | 의미 |
|---|---|
| split | 분류 작업을 분리한 프롬프트 구조 |
| integrated | 여러 작업을 한 응답에 통합한 구조 |
| with-description | 모델에게 각 카테고리 설명을 제공 |
| without-description | 카테고리 이름만 제공 |

각 조건에서 점수 임계값 `0.50`, `0.60`, `0.65`, `0.70`, `0.80`을 적용했다. 임계값이 낮으면 여러 카테고리를 더 쉽게 선택하고, 높으면 확신이 큰 카테고리만 선택한다.

## 왜 이 조건을 추천하나

### 1. 카테고리 설명은 넣는 편이 확실히 낫다

- split 구조 Top-1 정확도: 설명 포함 **82.1%**, 미포함 **73.1%**
- integrated 구조 Top-1 정확도: 설명 포함 **85.9%**, 미포함 **67.9%**

설명을 빼면 속도 이득은 거의 없거나 제한적인데 정확도는 크게 떨어진다. 따라서 **카테고리 설명 포함은 유지**하는 편이 좋다.

### 2. split이 integrated보다 훨씬 빠르다

| 후보 | Top-1 | 완화 정확도 | 평균 시간 |
|---|---:|---:|---:|
| split + 설명 + 0.65 | 82.1% | **87.2%** | **2.73초** |
| integrated + 설명 + 0.80 | **85.9%** | 85.9% | 14.20초 |

integrated는 Top-1이 3.8%p 높지만 약 **5.2배 느리다**. 반대로 split은 정답과 관련 카테고리를 함께 살리는 완화 정확도가 1.3%p 높다. 빠른 비동기 처리가 중요한 현재 서비스에는 split이 더 현실적이다.

### 3. 임계값은 0.65가 균형점이다

- 0.50~0.60: 정답 포함률은 같지만 불필요한 추가 카테고리가 많다.
- 0.65~0.70: 정확도는 유지하면서 추가 카테고리가 줄어든다.
- 0.80: 선택이 너무 보수적이 되어 정답 누락이 늘어난다.

0.65와 0.70의 측정 결과는 동일하다. 경계값에 가까운 후보를 조금 더 살리는 쪽을 택하면 **0.65**가 무난하다.

## 숫자를 어떻게 읽어야 하나

| 지표 | 쉬운 의미 | 권장 조건 결과 |
|---|---|---:|
| Top-1 Accuracy | 첫 번째 추천이 정답인 비율 | 82.1% |
| Exact Accuracy | 선택 결과가 정답 하나와 정확히 일치 | 76.9% |
| Relaxed Accuracy | 정답이 포함되고 추가 선택이 1개 이하 | 87.2% |
| Gold Coverage | 임계값 적용 후 정답 카테고리가 남아 있음 | 87.2% |
| Service Gold Coverage | 빈 결과 fallback 등 서비스 후처리까지 적용한 뒤 정답 포함 | 93.6% |
| Over-prediction Rate | 허용 범위를 넘는 과다 예측 | 0.0% |

**93.6%는 모델 단독 정확도가 아니다.** 빈 예측에 fallback을 적용하고 최대 반환 개수를 제한한 뒤의 서비스 결과다. 모델 자체를 비교할 때는 Top-1 82.1%, 임계값 적용 결과를 볼 때는 Relaxed 87.2%를 기준으로 보는 편이 맞다.

## 주요 오류 패턴

권장 조건에서 78건은 다음과 같이 나뉜다.

- 정확히 맞음: 60건
- 정답과 함께 관련 후보가 하나 더 있음: 8건
- 정답 카테고리를 놓침: 5건
- 아무 카테고리도 선택하지 못함: 5건

특히 `OTHER`가 취약하다.

- `OTHER` 정답 7건의 엄격 평가 recall/F1이 모두 0이다.
- `TEXT-021`, `TEXT-022`는 `IDEA_INSPIRATION`으로 잘못 분류했다.
- `TEXT-074`~`TEXT-078`은 빈 예측이 발생해 fallback을 사용했다.

그 밖에 반복적으로 보인 혼동은 다음과 같다.

- `LIFE_TASK` → `LEARNING_KNOWLEDGE`
- `CAREER` → `LEARNING_KNOWLEDGE`
- `IDEA_INSPIRATION` → `LIFE_TASK`

따라서 다음 개선 우선순위는 임계값 미세조정보다 **OTHER의 정의와 fallback 규칙 개선**, 그리고 서로 겹치는 카테고리의 경계 설명 보강이다.

## 이 결과의 한계

1. 데이터가 78건뿐이고 반복 실행이 1회라 모델 응답 변동성을 확인하지 못했다.
2. 정답 데이터는 문서당 카테고리 하나만 갖고 있다. 따라서 이 실험의 “다중 카테고리 완화 정확도”는 정식 multi-label 평가가 아니다.
3. 추가로 반환된 카테고리가 실제로 적절한지 정답 데이터로 완전히 검증할 수 없다.
4. `summaryParseSuccessRate`가 0으로 기록되어 있다. split 시나리오에서 요약을 평가 대상에서 제외한 것인지, 파싱 문제가 있었는지 실행 코드 확인이 필요하다. 분류 지표 해석과는 별도로 점검해야 한다.

## 다음 액션 제안

1. 1차 서비스 설정은 `split-with-description`, 임계값 `0.65`, 최대 2개 반환으로 적용한다.
2. `OTHER` 샘플과 fallback 정책을 먼저 재검토한다.
3. 혼동이 많은 카테고리 쌍에 제외 조건 또는 대비 예시를 설명에 추가한다.
4. 실제 다중 라벨 정답이 포함된 데이터셋을 별도로 만든다.
5. 같은 조건을 최소 3회 반복해 평균과 편차를 확인한 뒤 최종 확정한다.
